# OpenCode Go 实验性额度预测设计（修订版）

本文描述一个独立的实验性预测页面。该页面默认关闭，在“同步与数据”中打开开关后才启用。预测围绕每个模型的 5 小时、未来 24 小时、本周和本月四个口径展开，判断额度是否会提前用完，以及重置时是否还有剩余。

## 1. 本次修订

这次方案有四条明确约束。

第一，功能作为实验性内容处理。默认不显示预测页，也不执行预测相关的历史数据加载。开关放在“同步与数据”页，开启后才出现入口。

第二，额度以 Go 文档中每个模型的月额度为唯一基准。月额度为 `M` 时，周额度是 `M / 2`，5 小时额度是 `M / 5`。例如 DeepSeek V4.1 Flash 的月额度是 80，则周额度是 40，5 小时额度是 16。GPT 5.6 Luna 的月额度是 15，则周额度是 7.5，5 小时额度是 3。模型之间独立，不把不同模型的上限相加。

第三，四个结果卡以百分比为主。不同模型的绝对额度差异很大，80 美元只适合 DeepSeek，不能作为所有模型的统一展示值。百分比用于横向比较，绝对金额仅放在卡片副标题或悬浮提示中。

第四，预测页和现有性能页分开。现有的概览、趋势图、请求明细和同步逻辑保持不变，只在面板内增加一个独立预测视图，避免把额度计算、预测周期和现有性能图表混在一起。

## 2. 额度语义

### 2.1 单一模型额度

Go 文档的价格表中，每个模型已经带有 `Monthly limit`。这是该模型在当前套餐下的月额度。5 小时和周额度不再来自另一个计划总表，而是由月额度直接派生：

```text
monthly = monthlyLimitUsd
weekly = monthlyLimitUsd / 2
fiveHour = monthlyLimitUsd / 5
```

DeepSeek V4.1 Flash 在 Go 下：

```text
monthly = 80
weekly = 40
fiveHour = 16
```

GPT 5.6 Luna 在 Go 下：

```text
monthly = 15
weekly = 7.5
fiveHour = 3
```

不存在“同时还要满足一个月总额度 60、周总额度 30、5 小时总额度 12”的第二层约束。60、30、12 只是以月额度 60 为例的派生示例。预测计算只使用当前模型的 `monthlyLimitUsd`。

### 2.2 模型之间不共享额度

不同模型的额度互相独立。用户在“全部模型”视图下看到的是多行独立数据，不是把各模型额度相加后的总表。风险排序也只比较各模型自己的利用率，不计算一个虚假的“总套餐已用百分比”。

如果官方页面显示了一个总览 meter，它只能作为展示或校验信息。只有确认该 meter 对应当前选中模型时，才使用它的已用量作为该模型的官方基线。

### 2.3 24 小时的定位

`24h` 不是额度窗口，而是一个预测跨度。未来 24 小时可能跨越多个 5 小时窗口，也可能跨过 UTC 周重置。因此 24 小时预测需要单独计算，并检查它对当前 5 小时、周和月额度的后续影响。

24 小时卡片的百分比分母固定为月额度：

```text
24h 预测百分比 = 未来 24 小时预测消耗 / monthlyLimitUsd
```

这样不同模型的卡片可以直接比较。卡片副标题再显示绝对金额和 `p90`。

## 3. 实验性开关

### 3.1 入口位置

在“同步与数据”页增加一个独立的小节，例如：

```text
实验性功能
[ ] 启用额度预测（Beta）
根据本地请求记录和 Go 价格表预测 5h、24h、周和月额度。
预测结果仅供估算，不改变官方额度。
```

开关默认关闭。关闭时：

- 不显示预测标签页。
- 不加载预测所需的额外历史记录。
- 不执行模型额度计算。
- 不影响现有的同步、价格缓存、概览和图表。

开启时：

- 预测标签页出现，并标记 `Beta`。
- 首次打开预测页时加载预测所需的历史记录。
- 复用现有 `loadGoPricing()` 的文档价格缓存，不额外请求第二份价格数据。
- 用户切换模型、刷新同步或重新打开面板后，预测结果更新。

### 3.2 存储和状态

建议在 `src/constants.ts` 增加：

```ts
export const EXPERIMENTAL_FORECAST_KEY = 'experimentalForecast';
```

状态保存在 `localStorage` 的 `ocgo-lens:experimentalForecast` 中。默认值为 `false`。

`Panel` 只需要增加很少的接入点：

1. 读取并保存开关状态。
2. 在“同步与数据”页渲染复选框。
3. 根据开关显示或隐藏预测标签。
4. 如果关闭开关时用户正在预测页，自动切回“同步与数据”。
5. 打开预测页时才触发预测数据加载。

## 4. 数据来源和缓存

### 4.1 文档里已经有模型月额度

`https://opencode.ai/v2/docs/console/go/` 的价格表已经包含每个模型的 `Monthly limit`。不需要再引入一个独立的 `PlanCatalog`，也不需要为额度单独建立一套缓存文件或 IndexedDB store。

现有 `src/pricing.ts` 已经有 `GoPricingCache`，它保存从该文档页解析出的价格 tiers。只需要在同一个 cache 对象中增加一个模型额度映射：

```ts
interface GoPricingCache {
  fetchedAt: number;
  source: string;
  schemaVersion: 2;
  tiers: GoPricingTier[];
  quotaLimits: {
    go: Record<string, number | null>;
    'go-plus': Record<string, number | null>;
  };
}
```

例如：

```ts
quotaLimits: {
  go: {
    'deepseek-v4.1-flash': 80,
    'gpt-5.6-luna': 15,
  },
  'go-plus': {
    'deepseek-v4.1-flash': 160,
    'gpt-5.6-luna': 60,
  },
}
```

这里的 `null` 表示文档中的 Free 或 Unlimited。周额度和 5 小时额度不写入缓存，而是每次按 `M/2` 和 `M/5` 推导，避免出现三份可能不一致的数值。

### 4.2 价格和额度分开使用

`tiers` 仍然负责单请求价格：

- 输入、输出、缓存读、缓存写。
- 上下文阈值。
- Peak / Off-Peak。

`quotaLimits` 只负责该模型的月额度。两者来自同一张文档表，但在计算时分别使用。

`estimateModelCostBreakdown` 继续服务现有费用组成悬浮提示，它的结果会校准到实际 `costUsd`，不能拿来算套餐额度。预测页新增独立的单请求额度函数：

```ts
quotaUsdForRecord(record, tier)
```

它直接使用 `quotaLimits` 对应的价格和 Token 字段，不做实际费用缩放。

### 4.3 解析两张套餐表

当前 `parseGoPricingHtml` 只取第一张价格表。文档页面有 Go 和 Go Plus 两个 plan panel，需要分别解析：

- Go 表的模型月额度写入 `quotaLimits.go`。
- Go Plus 表的模型月额度写入 `quotaLimits['go-plus']`。
- 价格 tiers 在两张表中相同，只保留一份。
- 对同一模型的上下文档位和 Peak/Off-Peak 档位归入同一 `modelID`。
- 解析促销行时优先读取 `strong` 元素中的当前值。例如删除线 `$15` 后跟粗体 `$60` 时，当前额度应取 60，不能取第一个数字。

缓存 schema 从 1 升到 2，旧缓存自动失效。文档页面的价格缓存仍然保持 3 天，不需要为预测单独增加网络请求。

## 5. 独立预测页

预测页不修改现有概览、趋势图和模型表。它使用现有面板的 Shadow DOM、配色和基础组件，但渲染在一个新的 `forecast` 视图里。

建议新增：

```text
src/forecast.ts          纯预测和额度计算
src/ui/forecastPanel.ts  独立预测视图的 DOM 渲染
```

`Panel` 只负责：

- 读取实验开关。
- 在开关打开时创建/显示 `forecast` 标签。
- 复用现有模型筛选、价格缓存和同步状态。
- 把预测结果交给 `forecastPanel.ts` 渲染。

这样关闭实验功能时，现有四个标签页的行为保持原样。预测逻辑也可以单独测试，不需要改动现有性能图表。

## 6. 四个结果卡

### 6.1 5 小时卡

主值使用当前模型 5 小时额度百分比：

```text
5 小时
已用 51.0%
窗口结束预计 63.0%（p90 71.0%）
预计 17:40 触顶 / 或重置时剩余 37.0%
```

分母是该模型的 `monthlyLimitUsd / 5`。副标题显示绝对金额，例如 `8.2 / 16.0 USD`。

如果当前 5 小时窗口尚未开始，显示“首次使用后开始”，不显示虚假的触顶时间。

### 6.2 24 小时卡

主值使用未来 24 小时预测消耗占月额度的百分比：

```text
未来 24h
预计 8.0% 月额度
p90 10.1% · 折合 6.4 / 8.1 USD
```

这里的分母是月额度，不是另一个 24 小时额度。副标题注明是否会在 24 小时内触顶，以及是否会跨过 5 小时或周边界。

### 6.3 周卡

```text
本周
已用 55.0%
周重置预计 72.0%（p90 81.0%）
预计重置剩余 28.0% / 或提前触顶
```

分母是该模型的 `monthlyLimitUsd / 2`。同时显示周重置时间。

### 6.4 月卡

```text
本月
已用 64.0%
周期结束预计 83.0%（p90 91.0%）
预计重置剩余 17.0% / 或提前触顶
```

分母是该模型的 `monthlyLimitUsd`。预估超出 100% 时，主值用危险色并显示预计触顶时间。

### 6.5 全部模型模式

四张卡只对单个模型有意义。现有全局模型筛选为“全部”时，预测页应：

- 在顶部显示“最紧模型”的四张百分比卡。
- 下方显示每个模型独立的一行。
- 不计算一个把不同模型相加的总百分比。
- 允许点击模型行切换为单模型预测。

如果用户希望查看某个模型的四张卡，直接选择该模型即可。预测页的模型选择可以复用现有工具栏，也可以在预测页顶部提供紧凑的模型下拉框。

## 7. 模型明细表

表格以百分比为主：

| 模型 | 月额度 | 5h 已用/上限 | 周已用/上限 | 本月已用/月额度 | 24h 预测 | 周重置剩余 | 月重置剩余 |
|---|---:|---:|---:|---:|---:|---:|---:|
| GPT 5.6 Luna | $15 | 48% | 62% | 71% | 8% | 28% | 17% |
| DeepSeek V4.1 Flash | $80 | 22% | 41% | 52% | 5% | 38% | 24% |

表格中的“月额度”可以显示绝对值，因为它是额度基准；其余列以百分比为主。鼠标悬浮或点击单元格时，再显示绝对金额、`p10`、`p50`、`p90` 和重置时间。

预测曲线也按百分比绘制：

- 0% 到 100% 是当前模型的对应窗口额度。
- 历史实线、预测虚线、置信区间带。
- 5h、周、月分别使用各自的分母。
- 24h 图使用月额度作为分母，并标注它跨过的窗口边界。

## 8. 预测算法

### 8.1 5 小时预测

使用 5 分钟桶，结合最近 15 分钟、60 分钟的指数加权水平和同星期同时段的周期因子。当前 `sessionID` 仍在活跃时提高短期权重。预测到当前 5 小时窗口结束，输出已用百分比、预计剩余百分比和触顶时间。

### 8.2 24 小时预测

使用小时桶，按未来小时的星期和时段规律预测。24 小时没有独立上限，因此输出“未来 24 小时占月额度百分比”，并额外检查：

- 是否会跨过当前 5 小时窗口结束。
- 是否会跨过 UTC 周重置。
- 是否会在 24 小时内触发 5 小时或周额度上限。

### 8.3 周和月预测

周预测使用天桶和 UTC 周内周期，月预测使用天桶和付费周期内周期。预测到实际 `resetsAt`，而不是固定乘 7 或 30。长跨度增加趋势项，但趋势需要限制范围并显示更宽的置信区间。

### 8.4 置信度

输出 `p10 / p50 / p90`。主文案使用 `p50`，风险提示使用 `p90`。如果历史不足 24 小时、存在同步缺口、价格缓存过期或窗口重置时间未知，降低置信度并在卡片上标注。

## 9. 实施顺序

### 第一阶段：实验开关和独立入口

1. 增加 `EXPERIMENTAL_FORECAST_KEY`。
2. 在“同步与数据”页添加快捷开关。
3. 开关关闭时不显示预测标签。
4. 开关开启时显示 `forecast` 标签和 Beta 标记。
5. 关闭开关时自动切回“同步与数据”。

这一阶段不改现有概览、图表和请求明细。

### 第二阶段：从现有价格缓存读取模型额度

1. `src/pricing.ts` 解析 Go / Go Plus 两张表的月额度。

3. 增加 `quotaLimitsForModel` 和 `quotaUsdForRecord`。
4. 继续保留 `estimateModelCostBreakdown` 的现有行为。
5. 用 DeepSeek 80 和 GPT 15 的例子做单元测试。

### 第三阶段：预测引擎

1. 增加 `src/forecast.ts`。
2. 实现 5 小时、24 小时、周、月四条时间线。
3. 加入 `p10 / p50 / p90` 和置信度。
4. 输出触顶时间、重置剩余和百分比。

### 第四阶段：独立预测视图

1. 增加 `src/ui/forecastPanel.ts`。
2. 渲染四张百分比卡。
3. 渲染模型明细表和曲线。
4. 复用现有模型筛选、价格缓存和同步状态。
5. 增加空态、未定价、Free / Unlimited、窗口未开始等状态。

## 10. 验收标准

- 开关默认关闭，关闭时现有界面完全不受影响。
- 开关开启后才出现预测入口，才加载预测所需历史数据。
- 预测页使用现有 Go 价格缓存，不产生额外的价格请求。
- DeepSeek V4.1 Flash 的 Go 月额度 80 能推导出周 40、5h 16。
- GPT 5.6 Luna 的 Go 月额度 15 能推导出周 7.5、5h 3。
- 所有预测卡以百分比为主，绝对金额只作辅助。
- 24 小时被明确呈现为预测跨度，不被当作额度窗口。
- 全部模型视图不把不同模型额度相加。
- 关闭实验开关时不执行预测计算，也不会出现空的预测标签页。
- 现有费用组成、价格缓存、同步和性能图表测试继续通过。

## 11. 仍需确认

- 5 小时窗口的准确起止规则，以及 `startsAt` / `resetsAt` 的来源。
- 月付费周期的重置时间是否稳定可得。
- 文档中的促销优惠何时失效。
- `reasoningTokens` 是否已经包含在 output 计费中。
- 失败、拒绝、取消的请求是否计入模型额度。
- 官方页面总览 meter 与模型月额度不一致时的展示方式。
